MACHINE LEARNING · REGRESSION

共享单车需求预测

用两个神经网络在同一条基线上做回归——SKLearn 的 MLP 与 Keras，并解释高峰与天气如何影响租借量。

数据挖掘与机器学习 · 第 14 组课程作业

Bike Sharing Demand

以小时为粒度的租借量回归：10,886 行训练数据、2 个神经网络模型

题目来自 Kaggle Bike Sharing Demand：根据两年间逐小时记录的天气与时间信息，预测共享单车的租借数量。我们把时间字段拆成年月日与小时，对分类特征做独热编码、数值特征做标准化、对跨度大的数据取对数，然后在同一份 70/30 随机划分上分别训练 SKLearn 的 MLPRegressor 与 Keras 的 Sequential 模型，比较两者的拟合表现。

数据与预处理

没有缺失值，但需要处理两件事

数据集本身很干净，真正的难点是量纲差异过大的计数，以及形如 2011/1/1 1:00 的时间字段。

DATASET

数据概况

训练集 10,886 行 × 12 列：日期时间、季节、是否假日、是否工作日、天气等级、气温、体感温度、湿度、风速，以及 casual / registered / count 三个计数列。

10,886 × 12no missing values
FEATURES

时间拆解

把 datetime 拆成 年 / 月 / 日 / 星期 / 小时 五个字段，让模型能直接学到通勤高峰与季节规律。

yearmonthdayweekdayhour
SCALING

编码与标度

季节、天气、年、月、星期等分类特征做独热编码；气温、体感温度、湿度、风速做标准化；对差距过大的计数取对数。

OneHotEncoderStandardScalerlog transform

数据划分：按 0.7 的比例随机切分（train 7,619 / validation 3,265），并刻意打乱顺序，避免时间顺序本身泄漏信息。

解释性分析

租借量被什么驱动

报告与演示文稿给出的是定性判断，尚未做特征重要性或偏依赖的定量拆解。

TIME

通勤高峰

上下班时段租借量明显更高——这也解释了为什么把小时拆出来对模型帮助很大。

WEATHER

天气越好，两类用户都更多

天气良好时，非注册用户与注册用户的租借量都显著上升，说明天气是需求的首要外部变量之一。

CALENDAR

假日与非假日，租车理由不同

假日更可能来自游客等休闲需求，工作日则以上班族通勤为主——同一列 count 背后是两类不同的行为。

OTHERS

其余变量未继续深挖

气温、体感温度、湿度、风速都有影响，但团队判断分析过于复杂且缺少部分数据，没有进一步量化。

局限与自评

团队自己写下的不足

这部分直接来自报告与 PPT 的自评章节。

PERIOD

数据只覆盖 2011–2012 年

换到其他年份需要重新训练，模型本身没有跨时间的泛化保证。

EXTREMES

未针对极端情况训练

模型没有专门训练极端天气或极端需求的样本，团队自评「泛化能力较低」。

NO BASELINE

缺少基线对照

两个神经网络之间做了比较，但没有与线性回归或「用均值预测」这类朴素基线对照，因此 0.29 这个 RMSLE 究竟好到什么程度缺少参照。

REPRODUCIBILITY

超参未做搜索

隐藏层大小、学习率、批大小等都采用了一组设定而未做调参或交叉验证，模型性能仍有提升空间。

工程拆解

从原始表到可复用的预测程序

两个 notebook 各自独立完成一条完整链路，并把训练好的模型与预处理器一起保存，供交互式预测脚本调用。
