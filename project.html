项目案例

浙就来

面向浙江大学校园场景的配送服务平台

Vue 3 单页应用 + Flask REST 服务的校园配送平台：18 条前端路由（16 条受保护）、17 个接口、3 张数据表，串联注册登录、四步下单、地址簿、现金与积分双币支付和订单查询。

Vue 3.5 Vite 6 Vue Router 4 Pinia 3 Element Plus axios Flask 3 Flask-SQLAlchemy PyJWT SQLite

01

业务问题

校园配送信息分散，履约流程缺少统一入口

学生在外卖、快递与校内物品配送场景中，需要重复沟通取件位置、收货地址、费用和进度，信息容易遗漏。

产品方案

平台围绕学生身份构建统一账户，用分步表单降低下单复杂度，并通过订单状态和个人中心沉淀完整服务记录。

核心业务流

从需求提交到订单履约

01 INPUT

提交需求

填写物品名称、取件柜与备注，支持加急配送。

02 LOCATION

确认地址

选择常用地址或输入新地点，绑定当前用户。

03 PAYMENT

选择支付

按普通或加急规则计算现金与积分费用。

04 STATUS

追踪订单

查看订单列表、详情、状态并支持再次下单。

数据模型

三张表撑起完整业务闭环

SQLAlchemy ORM 定义 users / addresses / orders 三个模型，通过 user_id 外键串联，所有读写按用户隔离。

TABLE / users

用户与身份

账户、校区与积分余额

  • student_idunique · 10 digits
  • public_iduuid4
  • passwordpbkdf2:sha256
  • pointsdefault 100
  • campuslogin check
  • last_logindatetime

TABLE / addresses

常用地址

用户级地址簿与默认地址

  • user_idFK → users.id
  • icontype tag
  • titlelocation name
  • detailfull address
  • timeavailability
  • is_defaultboolean

TABLE / orders

订单与计价

草稿到支付的完整状态

  • order_iduuid4
  • user_idFK → users.id
  • food_nameitem
  • locker_infopickup point
  • is_urgentpricing flag
  • delivery_addressdrop-off
  • receiver_addressresolved
  • delivery_fee_cash5.0 / 7.0
  • delivery_fee_points50 / 70
  • payment_statusdraft→pending→paid

业务规则

把规则写进代码，而不是文档里

从计价到鉴权，每条业务约束在服务端都有对应的校验与实现。

PRICING

双向计价：现金与积分同价

普通 ¥5 / 50 积分，加急 ¥7 / 70 积分，固定 1 元 = 10 积分；下单瞬间同时写入两种费用字段，用户可自由选择支付货币。

¥5 / 50 pts¥7 / 70 pts1 : 10
VALIDATION

身份校验前置到接口层

学号必须匹配 10 位数字、手机号匹配 1[3-9] 开头共 11 位，注册时还会检查学号与手机号是否已被占用。

^\d{10}$^1[3-9]\d{9}$409 dup
AUTH

令牌鉴权与会话守卫

后端用 @token_required 装饰器解析 HS256 令牌并回查用户，令牌 24 小时过期；前端 router.beforeEach 拦截未登录访问。

HS25624h exp@token_required
ISOLATION

用户级隔离与上传安全

地址与订单查询强制携带 user_id 过滤，越权 ID 返回 404；上传仅允许 png/jpg/jpeg/gif，限制 5MB 并用 UUID 重命名防覆盖。

user_id filter5 MB capuuid filename
